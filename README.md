# OPTIAV - 브라우저 기반 간편 동영상 편집·인코딩 도구

> **"설치 없이 브라우저에서 동영상을 자르고 변환하세요."**  
> 영상 파일은 서버로 전송되지 않으며, 사용자의 브라우저 내부(100% Client-side Sandbox)에서 분석, 편집, 인코딩됩니다.

---

## 📌 1. 프로젝트 개요

**OPTIAV**는 별도의 무거운 비디오 편집 소프트웨어를 설치하지 않고도 웹 브라우저에서 즉시 동영상을 손쉽게 다듬고 최적화할 수 있는 고성능 웹 애플리케이션입니다.

- **절대적 개인정보 및 보안**: 영상 파일 및 메타데이터가 서버에 일절 업로드되지 않습니다.
- **듀얼 하이브리드 인코딩 파이프라인**:
  1. **FFmpeg.wasm (WebAssembly)**: 고정밀 CRF 품질 압축, H.264/AAC MP4, VP9 WebM, 팔레트 최적화 고화질 GIF 출력 지원
  2. **하드웨어 가속 Canvas/MediaRecorder**: SharedArrayBuffer 제한 환경이나 저사양 모바일 기기에서도 100% 즉시 동작하는 실시간 브라우저 가속 폴백 엔진

## ⚡ 2. 주요 기능

### 1) 동영상 업로드 & 상세 메타데이터 분석
- 드래그 앤 드롭(Drag & Drop) 및 파일 탐색기 지원
- 지원 포맷: MP4, MOV, WebM, AVI, MKV, M4V 등
- 즉시 체험 가능한 **HD 샘플 영상 생성기** 내장 (파일이 없어도 1초 만에 전체 편집 기능 테스트 가능)
- 파일명, 용량(MB/GB), 재생 시간(HH:MM:SS), 원본 해상도, 추정 FPS, 비디오 코덱, 오디오 유무 자동 감지 및 시각화

### 2) 비디오 프리뷰어 & 프레임 단위 이동
- 재생 / 일시정지, 볼륨 및 음소거 토글, 전체화면
- 1초 전/후 건너뛰기 및 **프레임 단위(±1 frame) 정밀 탐색**
- 회전 각도 및 좌우 반전 실시간 프리뷰

### 3) 썸네일 기반 타임라인 트리밍 (자르기)
- 비디오 전체 구간에서 추출된 **필름스트립 썸네일 트랙** 시각화
- 시작점(Start)과 종료점(End) 듀얼 핸들 드래그
- 밀리초(ms) 단위 수치 직접 입력 및 "현재 위치를 시작/종료점으로 설정" 원클릭 버튼
- 선택된 클립의 순수 재생 시간 실시간 계산

### 4) 화면 크기(해상도) 변경
- 프리셋 제공:
  - 원본 해상도 유지
  - 4K UHD (3840 × 2160)
  - 2K QHD (2560 × 1440)
  - FHD 1080p (1920 × 1080)
  - HD 720p (1280 × 720)
  - SD 480p (854 × 480)
  - 360p (640 × 360)
  - 사용자 지정 (가로세로 비율 유지 옵션 잠금/해제)

### 5) 화면 비율 변경 (Fit vs Fill)
- 프리셋: 원본, 16:9 (유튜브/가로), 9:16 (쇼츠/릴스/틱톡), 4:3 (클래식), 1:1 (정사각형), 4:5 (인스타그램 피드), 사용자 지정
- **Fit (맞춤)**: 영상 전체를 보존하고 남는 여백을 커스텀 배경색(블랙, 화이트, 다크 슬레이트 등)으로 레터박스 처리
- **Fill (채움)**: 비율에 맞춰 화면을 꽉 채우고 초과 영역 크롭

### 6) 대화형 화면 크롭 (Interactive Crop)
- 플레이어 화면 위에서 직접 마우스로 드래그 가능한 인터랙티브 크롭 박스
- 3분할 가이드 그리드 및 모서리 리사이즈 핸들(NW, NE, SW, SE)
- 크롭 비율 고정 지원: 16:9 고정, 9:16 고정, 1:1 고정, 4:3 고정, 자유 크롭

### 7) 회전 및 속도 (배속)
- 90° 오른쪽(시계방향), 90° 왼쪽(반시계방향), 180° 회전 및 좌우 반전(Flip)
- 재생 속도 조절: 0.25x, 0.5x, 1x, 1.25x, 1.5x, 2x 및 사용자 지정 슬라이더

### 8) 오디오 처리
- 오디오 유지 vs 오디오 제거(음소거) 원클릭 선택
- 오디오 볼륨 조절 슬라이더 (0% ~ 200% 증폭)

### 9) 출력 포맷 & GIF 변환
- **MP4**: H.264 + AAC (대부분의 기기/SNS에서 가장 높은 호환성)
- **WebM**: VP9 + Opus (웹 환경에 최적화된 높은 압축 효율)
- **GIF**: 애니메이션 움직이는 짤 (GIF FPS 10/15/20 및 최대 가로 해상도 최적화로 불필요한 용량 폭증 방지)

### 10) 용량 최적화 및 목표 용량 (Target Size) 기능
- **빠른 압축**: CRF 28 기반 파일 크기 최소화
- **균형**: CRF 23 기반 일상적 표준 밸런스
- **고품질**: CRF 18 기반 원본 화질 보존
- **목표 용량 기능**: 카카오톡/디스코드/이메일 첨부 제한에 맞춘 MB 단위 입력 (예: `25 MB`)  
  공식: $\text{Target Bitrate} \approx \frac{\text{Target Size (MB)} \times 8192}{\text{Duration (s)}} - \text{Audio Bitrate}$  
  비트레이트를 동적으로 산출하여 인코딩 전 **예상 용량**을 실시간 안내
- 고급 모드: CRF 수동 슬라이더(16~35), 비트레이트 kbps, 출력 FPS(15, 24, 30, 60) 직접 설정

### 11) 인코딩 진행 모달 & 비동기 취소
- Web Worker 기반 UI 블로킹 없는 부드러운 진행률(%) 표시
- 현재 처리 시간 및 예상 남은 시간 실시간 계산
- 언제든지 즉시 중단할 수 있는 [인코딩 취소] 지원
- 상세 인코더 콘솔 로그 실시간 스트림 뷰어

### 12) 결과 화면 & 파일 크기 비교
- 원본 크기 vs 결과 크기 vs **용량 절감율(%)** 시각적 통계 배지
- 결과 영상 즉시 재생 및 원클릭 다운로드
- [다시 편집하기] 및 [새 영상 불러오기] 워크플로우

## 🌐 5. Cloudflare Pages 정적 배포 가이드

OPTIAV는 순수 클라이언트 사이드 정적 웹 애플리케이션으로, Cloudflare Pages에 단 1분 만에 배포할 수 있습니다.

### 1) 빌드 설정
- **Framework Preset**: `Vite`
- **Build Command**: `npm run build`
- **Build Output Directory**: `dist`

### 2) COOP/COEP 헤더 설정 (`public/_headers`)
FFmpeg.wasm의 멀티스레드 가속 및 SharedArrayBuffer 기능을 위해 프로젝트의 `public/_headers` 파일에 다음과 같은 보안 헤더가 설정되어 있습니다.

```http
/*
  Cross-Origin-Opener-Policy: same-origin
  Cross-Origin-Embedder-Policy: credentialless
```

> **참고**: `credentialless` 방식을 적용하여 CDN(unpkg, jsdelivr)에서 불러오는 WASM 바이너리 파일이 차단되지 않으면서도 브라우저 보안 격리가 정상 활성화됩니다. 단일 스레드 환경에서도 캔버스 폴백 엔진이 자동 전환되므로 어떤 호스팅 환경에서도 완벽히 작동합니다.

## 📋 7. 테스트 검증 시나리오

개발 및 릴리스 시 다음 테스트를 수행하였습니다.

1. **용량별 검증**:
   - 10MB 소형 영상 (SNS 짤용)
   - 100MB 중형 영상 (FHD 브이로그)
   - 500MB 이상 대용량 영상 (OPFS 및 메모리 누수 방지 스트리밍 확인)
2. **해상도 및 비율 검증**:
   - 9:16 세로 숏폼 영상 (쇼츠, 릴스)
   - 16:9 가로 영상 (FHD, 4K UHD)
   - 1:1 정사각형 영상 (인스타그램)
3. **포맷 및 코덱 호환성**:
   - MP4 (H.264/AAC), WebM (VP9/Opus), MOV (애플 기기 촬영물), MKV
   - 오디오 트랙이 없는 영상 (무음 영상 트리밍 및 인코딩 시 크래시 방지)
   - GIF 출력 및 팔레트 렌더링
4. **인터랙션 안정성**:
   - 인코딩 진행 도중 [취소] 버튼 클릭 시 즉시 리소스 해제 확인
   - 브라우저 UI 멈춤 현상(Freezing) 방지 및 반응형 레이아웃 확인

## 🔒 8. 보안 및 개인정보 보증

- 사용자가 업로드한 비디오는 서버로 절대 전송되지 않습니다.
- 백엔드에 사용자 영상 저장을 위한 API나 데이터베이스를 두지 않습니다.
- 모든 영상 인코딩은 오직 사용자의 컴퓨터/스마트폰 CPU 및 GPU 브라우저 인스턴스 안에서만 이루어집니다.
